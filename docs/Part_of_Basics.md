## 一、点云与 LiDAR

### 点云是什么

点云是三维空间中一组点的集合。每个点通常包含空间坐标 (x, y, z)，并可附带属性：反射强度、点所在线束编号、采样时刻等。

点云本身不包含拓扑关系（哪些点连成面），需要下游算法通过邻域分析推断几何结构。

### LiDAR 如何产生点云

LiDAR 通过发射激光脉冲、测量回波往返时间得到目标距离，结合发射时的方向，确定目标在传感器坐标系中的位置 (x, y, z)。多个脉冲依次采集，形成一帧点云。

按扫描方式分为两类：

```text
机械旋转式：整体旋转覆盖 360 度视场
固态 / 半固态：通过微振镜或光学相控阵扫描有限视场
```

Livox Mid-360 属于非重复扫描，每个时刻的扫描轨迹不重合，视场覆盖随时间累积。

### 帧的概念

LiDAR 通常按固定时间窗口组织点云，一帧对应一次完整扫描。本录包点云帧率约 10 Hz，即每帧时长约 0.1 秒。

每帧点云携带两类时间信息：

```text
帧头时间戳 header.stamp    该帧的起始时刻
每点时间戳 timestamp       该点实际采样的绝对时刻
```

### 为什么一帧内各点时间不同

LiDAR 不是瞬时拍下一整幅图。以旋转扫描为例，雷达在 0.1 秒内连续转动，每一刻采集少量点，整帧点云由这 0.1 秒内先后采集的点拼接而成。

所以帧内第一个点与最后一个点的时间相差可达 0.1 秒。帧头时间戳一般对应第一个点。

这一点决定了去畸变的必要性：若帧内机器人运动，各点是在不同位姿下测得的，直接拼接会错位。

## 二、IMU

### IMU 测量什么

IMU 通常包含两类传感器：

```text
加速度计    测量三轴线加速度
陀螺仪      测量三轴角速度
```

采样率远高于 LiDAR（本录包约 200 Hz，即每 5 ms 一组数据）。输出通常包含时间戳、三轴线加速度、三轴角速度，部分 IMU 还输出姿态，但本录包不使用。

### 比力与重力

加速度计测量的是比力，不是直接的加速度。

比力的定义：

```text
f = a - g
```

其中 a 是物体相对惯性系的加速度，g 是重力加速度向量（指向地心）。加速度计输出 f，单位 m/s²。

静止时 a = 0，所以 f = -g。重力加速度指向下方，因此 -g 指向上方，加速度计静止时的读数方向为竖直向上，大小约 9.8 m/s²。

本录包的原始 `linear_acceleration` 以 g 为单位，节点先乘 `acc_scale` 再当作 m/s² 使用；上面讨论的是换算后的物理量。

这一物理事实是重力对齐（`gravityAlignment`）的依据：静止时加速度计读数在世界系中指向天顶；但它在 IMU 系中的三轴分量由传感器安装姿态决定。重力对齐就是用这些分量估计 IMU 相对重力方向的姿态。

### 为什么 IMU 频率高于 LiDAR

机器人运动是连续的，LiDAR 帧率只有 10 Hz，两帧之间位置和姿态可能已大幅变化。仅凭 LiDAR，无法知道帧间运动。

IMU 以 200 Hz 采样，每 5 ms 提供一次角速度与加速度。将这些测量积分，可以在 LiDAR 帧之间预测位姿变化，为配准提供初值，为去畸变提供帧内位姿序列。

LIO 的基本结构由此而来：

```text
IMU 高频积分   -> 帧间运动预测、帧内位姿序列
LiDAR 低频观测 -> 修正累积误差、提供绝对位姿
```

## 三、刚体变换

### 位姿 = 旋转 + 平移

机器人的位姿由两部分组成：

```text
姿态（旋转）  机体坐标系相对世界坐标系的朝向
位置（平移）  机体坐标系原点在世界坐标系中的坐标
```

数学上用一个 4x4 齐次变换矩阵 T 表示，写成：

```text
T = [ R  t ]
    [ 0  1 ]
```

其中 R 是 3x3 旋转矩阵，t 是 3x1 平移向量。T 作用到一个点上，先旋转再平移：

```text
p_world = R * p_body + t
```

在代码中对应 `Eigen::Isometry3d`。命名 `T_a_b` 表示"将 b 系中的点变换到 a 系"。例如 `T_world_imu` 表示 IMU 系到世界系的变换。

### 旋转的三种表示

| 表示 | 参数个数 | 优点 | 缺点 |
|---|---:|---|---|
| 旋转矩阵 | 9（约束后 3 自由度） | 直接用于变换运算 | 元素不独立，不便插值 |
| 欧拉角 | 3 | 直观，可读 | 有万向锁，绕圈时数值跳变 |
| 四元数 | 4（约束后 3 自由度） | 紧凑，无奇点，适合插值 | 不直观 |

本项目在表示位姿时用 `Isometry3d`（内部是旋转矩阵 + 平移），在插值时转换为四元数。原因见下节。

### 为什么插值要用四元数

去畸变需要在两个已知位姿之间求中间时刻的位姿。平移可线性插值，旋转不行。

旋转矩阵的 9 个元素并不独立：三列必须是单位正交向量，行列式为 1。对 9 个元素直接线性插值，得到的矩阵几乎必然不满足这些约束，不再是一个旋转。

四元数是 4 维单位向量，满足 w² + x² + y² + z² = 1。所有四元数位于 4 维单位球面上。两个四元数之间的最短路径，就是球面上的大圆弧。沿此弧按比例移动，即得中间旋转。这一操作称为 slerp（球面线性插值）。

四元数有一个性质需要注意：q 与 -q 表示同一旋转，但直接插值时可能走远弧。slerp 内部处理该问题，前提是传入单位四元数——从旋转矩阵构造所得即满足。

### 齐次坐标与 4x4 变换矩阵

齐次坐标将 n 维点扩展为 n+1 维：

```text
三维点 (x, y, z)  ->  齐次坐标 (x, y, z, 1)
方向向量 (dx, dy, dz) -> 齐次坐标 (dx, dy, dz, 0)
```

第四个分量 w = 1 表示位置点，w = 0 表示方向。

好处是：旋转与平移可以用一个 4x4 矩阵统一表示，多次变换连乘即可组合。例如：

```text
p_world = T_world_imu * T_imu_lidar * p_lidar
```

对应代码中的 `Eigen::Vector4d`。协方差也保持 4x4 以与这一表示一致，详见第四节。

## 四、协方差与特征分解

### 协方差的统计意义

给定一组三维点，协方差矩阵描述它们在各个方向上分布的程度以及各方向之间的相关性。

3x3 协方差矩阵定义：

```text
cov = (1/k) * Σ (p_i - mean) * (p_i - mean)^T
```

其中 k 是点的个数，mean 是均值。

矩阵元素含义：

```text
cov(i, j)  第 i 维与第 j 维的协方差
cov(i, i)  第 i 维的方差
```

方差大表示点在该方向分布广，方差小表示分布集中。非对角线元素表示两维之间的相关程度。

代码中实际使用等价的展开式以减少减法：

```text
cov = (1/k) * Σ p_i * p_i^T - mean * mean^T
```

注意除以 k（总体协方差），不是 k-1（无偏样本协方差）。

### 特征值 / 特征向量 / 特征分解

协方差矩阵是实对称的，存在一组互相正交的特征向量 v_1, v_2, v_3，以及对应的特征值 λ_1 ≤ λ_2 ≤ λ_3，满足：

```text
cov * v_i = λ_i * v_i
```

这一分解记为：

```text
cov = V * diag(λ_1, λ_2, λ_3) * V^T
```

其中 V 的三列是三个特征向量。

几何直觉：特征向量表示点分布的主方向，特征值表示该方向上的方差（分布宽度）。

### 为什么平面点的最小特征值接近 0

若一组点分布在一个平面上：

```text
沿平面法向：点几乎无分布  ->  该方向方差约 0  ->  最小特征值 λ_1 接近 0
沿平面内两个切向：点有分布  ->  另外两个特征值明显大于 0
```

最小特征值对应的特征向量即平面法向。

实际点云有噪声，λ_1 很小但不严格为 0。GICP 用它构造约束时，法向方向权重会非常大（1/λ_1），数值微小扰动即导致法向大幅偏转。工程上常把平面点的特征值统一替换为 `(1e-3, 1, 1)`，使法向权重保持在固定量级。这就是平面协方差正则化（`regularizePlaneCovariance`）的由来。

正则化保留特征向量（平面朝向不变），只替换特征值：

```text
cov_reg = V * diag(1e-3, 1, 1) * V^T
```

## 五、配准与 ICP

### 配准在做什么

配准（registration）的任务是：给定两帧点云，求它们之间的相对位姿，使得两帧点云在空间上尽可能重合。

在 LIO 中，前一帧点云（或累积的局部地图）作为目标，当前帧点云作为源，配准得到当前帧相对目标帧的位姿。再结合上一帧的世界位姿，即可推出当前帧的世界位姿。

配准是 LIO 的核心观测环节：IMU 提供预测，配准提供观测修正。

### ICP 的基本思想

ICP（Iterative Closest Point）是最基础的配准算法，迭代执行以下步骤：

```text
1. 以上一步的位姿估计为初值，将源点云变换到目标坐标系
2. 对每个源点，在目标点云中找最近邻点，作为对应点
3. 根据当前对应关系，求使对应点距离平方和最小的位姿
4. 更新位姿，若变化小于阈值则停止，否则回到步骤 2
```

ICP 有两个关键弱点：

```text
初值敏感      初值偏差大时，最近邻对应关系错误，可能收敛到错误结果
局部最优      无全局搜索机制
```

LIO 中，IMU 预积分恰好提供了较好的初值，这是 LIO 相比纯 ICP 稳定的根本原因。

### GICP 与 ICP 的区别

GICP（Generalized ICP）在 ICP 基础上做了两处扩展：

```text
1. 每个点除坐标外，还携带局部协方差（由邻居计算）
2. 对应点之间的误差用马氏距离（考虑协方差的加权距离）而不是欧氏距离
```

直觉上：若一个点位于平面上，则法向方向的约束应强，切向方向的约束应弱。协方差编码了这一各向异性，使配准结果在平面方向上更准确。

本项目使用的协方差就是第四节所述由邻居点计算并正则化后的 4x4 矩阵。`computeCovariance` 与 `regularizePlaneCovariance` 写错，GICP 的约束权重即偏离，轨迹精度下降。

## 六、关键帧与因子图

### 关键帧是什么、为什么需要

若每一帧 LiDAR 都插入地图，地图点会随运行时间线性增长，内存和计算开销均无法承受。此外相邻帧之间运动量很小，直接插入会带来大量冗余。

关键帧策略：只有当新帧的位姿相对上一关键帧的运动量（平移或旋转）超过阈值时，才将其插入地图。

本项目在 `mapping_utils.cpp` 的 `isKeyframePose` 中按平移阈值和旋转阈值判断。`params_mapping.yaml` 中的 `keyframe_trans_thresh` 与 `keyframe_rot_thresh` 是这两个阈值。

### 因子图在做什么

因子图（factor graph）是求解优化问题的一种表示。图中包含两类元素：

```text
变量（节点）  待估计的量，如每帧的位姿、速度、IMU 零偏
因子（边）    对变量之间关系的约束，附带噪声模型
```

优化目标：找到一组变量取值，使所有因子的误差项加权平方和最小。数学上是最小二乘问题，通常用高斯-牛顿或列文伯格-马夸尔特法迭代求解。

LIO 中的因子包括：

```text
IMU 因子      连接相邻两帧的位姿、速度、零偏，约束来自 IMU 预积分
配准因子      连接当前帧位姿与局部地图，约束来自 GICP
先验因子      固定初始帧，消除全局自由度
零偏因子      约束相邻帧的 IMU 零偏变化
```

本项目使用固定滞后滑窗：只优化最近 3 秒内的位姿（`smoother_lag = 3.0`），更早的位姿固定不变。这样每帧的计算量不随时间增长。

### 预积分是什么

IMU 以 200 Hz 输出测量。若把每一次测量作为一个因子，2 帧 LiDAR 之间会有约 20 个 IMU 因子，因子图规模迅速膨胀。

预积分的思想：把两帧之间的所有 IMU 测量，提前积分成一个"相对运动约束"，对应一个 IMU 因子。积分的结果包括：

```text
相对旋转
相对平移
相对速度变化
噪声传播得到的协方差
```

这样因子数量与 LiDAR 帧数同阶，不随 IMU 采样率增加而膨胀。积分结果的协方差描述了该段 IMU 数据的不确定性，供优化时加权使用。

预积分的具体计算由 `imu_integration.cpp` 完成，本项目已提供，无需实现。

## 七、ROS 2 与 Eigen 速查

### 话题、消息、TF、frame_id

```text
节点 Node        ROS 2 中的计算单元
话题 Topic       节点之间通信的命名通道
消息 Message     话题中传递的数据结构，带有类型
发布者/订阅者    向话题发送 / 从话题接收消息的节点
```

本项目订阅两个话题：

```text
/livox/lidar/pointcloud   sensor_msgs/msg/PointCloud2
/livox/imu                sensor_msgs/msg/Imu
```

`frame_id` 是消息头中的一个字段，指明该消息中的坐标数据属于哪个坐标系。

TF 是 ROS 2 中管理坐标系变换的机制。TF 树是一棵有向树，每条边是一个带时间戳的变换。本项目发布的 TF 链：

```text
odom -> imu_link -> lidar_link
```

读法：`odom` 是父坐标系，`imu_link` 是子坐标系，`odom -> imu_link` 这条边表示从 `imu_link` 到 `odom` 的变换 `T_odom_imu`。

QoS 是 ROS 2 的通信质量配置。`SENSOR_DATA` 预设对应 `BEST_EFFORT`（尽力传输，不重发），适合高频传感器数据；`RELIABLE` 保证送达，但可能因重发导致延迟累积。本项目的 IMU/LiDAR 订阅分别使用 `rclcpp::QoS(3)` 和 `rclcpp::QoS(1)`，采用默认的 `RELIABLE` 可靠性，而不是 `SENSOR_DATA` 预设。

### Eigen 常用操作

本项目用到的主要类型和操作：

```cpp
// 位姿：4x4 齐次变换矩阵，旋转 + 平移
Eigen::Isometry3d T = Eigen::Isometry3d::Identity();
T.linear()      // 旋转部分（3x3）
T.translation() // 平移部分（3x1）

// 齐次坐标：用于 4x4 协方差与变换
Eigen::Vector4d p(x, y, z, 1.0);

// 四元数
Eigen::Quaterniond q(T.linear());        // 从旋转矩阵构造
Eigen::Quaterniond q_b = Eigen::Quaterniond::Identity();  // 另一姿态的四元数
const double t = 0.3;
Eigen::Quaterniond q2 = q.slerp(t, q_b);  // 球面插值
q.toRotationMatrix();                     // 转回旋转矩阵

// 从向量构造旋转：把 a 转到 b 的最短弧
Eigen::Quaterniond::FromTwoVectors(a, b);

// 绕轴旋转
Eigen::AngleAxisd(angle, Eigen::Vector3d::UnitZ());

// 协方差的特征分解
Eigen::SelfAdjointEigenSolver<Eigen::Matrix3d> eig;
eig.computeDirect(cov3x3);
eig.eigenvalues();   // 升序排列
eig.eigenvectors();  // 对应特征向量按列排列

// 与 gtsam 类型互转
gtsam::Pose3 pose(T.matrix());  // Isometry3d -> Pose3
Eigen::Isometry3d T2(pose.matrix());  // Pose3 -> Isometry3d
```

若上述操作有未接触过的，可在项目代码中搜索用法。各模块文档只说明算法逻辑，不重复解释 Eigen 接口。
